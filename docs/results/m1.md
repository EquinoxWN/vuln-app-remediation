## Analyze

All 7 exploits fire as designed (7/7, target met). One defect was found outside the catalogued flaws:
`VULN_APP_PORT` was parsed with a bare `int()`, so bad input gave a traceback (root cause: env input
not validated). The pip in the venv itself had PYSEC-2026-3721 (tool, not a project dependency).

## Improve

`VULN_APP_PORT` is now validated (integer, 1024..65535, exit 2 otherwise) with 5 tests; the venv pip
was upgraded to 26.2 and the audit is clean. Mutation testing: 8/8 hand mutants killed
([quality check](../quality/2026-11-01.md)).

## Control

CI on every push: ruff, `mypy --strict`, pytest with a `::notice` of the result line, `pip-audit`,
and a container job that runs the suite with `--network none --read-only --cap-drop ALL --memory
256m` as a non-root user. The exploit guard and write-up tests block adding a flaw without its proof
and write-up.

## What is CI-only

- The Docker build and the in-container test run (no Docker on this machine by rule).
- Python 3.12 (local run used 3.14.5).

## Deviations from the backlog wording

- **Branches:** the portfolio keeps a single `main` branch, so the vulnerable app lives on `main`;
  M2 patches the same routes and the exploit tests invert into regression tests.
- **Burp Suite:** the proofs of concept are automated tests, not Burp captures (ADR 0002). Burp was
  not used. Anyone can still run the lab on loopback and inspect it with a proxy.
- **Docker:** the image runs the suite with no network; serving the app from a container is not part
  of M1 (the app binds to loopback by design, ADR 0003).
